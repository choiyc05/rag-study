# 실험 기록

**이 프로젝트의 결과물은 동작하는 챗봇이 아니라 이 표다.**
"무엇을 바꿔서 몇 점에서 몇 점이 됐는가"를 남긴다.

작성 규칙은 [roadmap.md](roadmap.md) 참고. 아직 실험 전이라 표는 비어 있다.

---

## 기록 규칙

1. **한 행 = 변수 하나 변경.** 두 개를 동시에 바꿨으면 두 행으로 쪼개거나, 쪼갤 수 없으면
   비고에 명시한다. 안 그러면 나중에 어느 쪽이 이겼는지 알 수 없다.
2. **효과가 없거나 나빠진 실험도 지우지 않는다.** 음성 결과가 절반의 가치다.
   "하이브리드를 넣었는데 안 올랐다"도 결과이고, 안 남기면 6개월 뒤에 또 해본다.
3. **직전 행 대비가 아니라 명시한 기준선 대비**로 증감을 적는다.
4. 숫자를 못 재는 변경(리팩터링 등)은 여기 적지 않는다. 커밋 메시지로 충분하다.

## 지표 정의

| 지표 | 정의 |
|---|---|
| `Hit Rate@k` | 정답 문서가 상위 k 안에 있는 질의의 비율. 정답이 1개이므로 `Recall@k`와 같은 값 |
| `MRR` | 정답 순위의 역수 평균. 정답이 얼마나 위에 있는가 |
| `지표 2` | Gemini가 "이 검색 결과가 질문에 답이 되는가"를 채점. 절대 성능용 |

⚠️ **지표 1의 절대값은 과대평가된다.** 질의가 정답 행에서 파생된 것이라
"Hit Rate@5 = 0.87"을 실력이라 믿으면 안 된다. **A vs B 비교에만 쓴다.**

## Phase 0 — 임베딩 모델 비교

같은 평가셋, 같은 전처리, 브루트포스 검색(DB 없음). 변수는 모델 하나.

| ID | 모델 | 차원 | prefix | Hit@1 | Hit@5 | Hit@20 | MRR | 임베딩 시간 | 비고 |
|---|---|---:|---|---:|---:|---:|---:|---:|---|
| E-1 | `nlpai-lab/KURE-v1` | 1024 | | | | | | | |
| E-2 | `BAAI/bge-m3` | 1024 | | | | | | | |
| E-3 | `Alibaba-NLP/gte-multilingual-base` | 768 | | | | | | | |

E-1과 E-2는 base가 같아 **변수가 "한국어 튜닝" 하나뿐**이다.
E-3은 다른 질문 — "절반 크기 768차원으로 충분한가?"

⚠️ **prefix 컬럼을 비워두지 말 것.** E5 계열은 `query: `/`passage: `가 필수이고,
빠뜨리면 성능이 떨어지되 **에러가 안 나서** "이 모델 별로네"라고 오판하게 된다.
모델 카드 예제를 그대로 따랐는지 여기에 적는다.

**확정 모델:** (미정) · **확정 차원:** (미정) — 이 값이 DB 스키마를 결정한다.

## Phase 1 — 검색 고도화

기준선 = Phase 0 승자 모델의 단순 벡터 검색.

| ID | 변경 내용 | Hit@1 | Hit@5 | Hit@20 | MRR | Δ MRR | 지연(ms) | 판정 |
|---|---|---:|---:|---:|---:|---:|---:|---|
| B-0 | **기준선** (벡터 단독) | | | | | — | | — |
| R-1 | 임베딩 대상: 질문 → 질문+답변 | | | | | | | |
| R-2a | 리랭커 568M `bge-reranker-v2-m3` (후보 20 → 5) | | | | | | | |
| R-2b | 리랭커 306M `gte-multilingual-reranker-base` | | | | | | | |
| R-2c | R-2 승자 + `max_length` 512 → 320 | | | | | | | |
| R-3 | 하이브리드 BM25 + RRF(k=60) | | | | | | | |
| R-4 | 메타데이터 필터 (`department`) | | | | | | | |
| R-5 | 후보 수 20 → 50 | | | | | | | |
| R-6 | **긴 QA 의미 분해** (복합 질문 → 독립 질문 N행, payload 공유) | | | | | | | |

**R-6은 대상을 나눠서 잰다.** 전체 평균만 보면 8%짜리 변경의 효과가 묻힌다.
분해 대상이 된 행(질문 표현 3개 이상, 16.3%)에서 나온 질의만 따로 집계할 것.
전체가 그대로여도 해당 구간이 올랐으면 성공이다.

**지연 컬럼을 반드시 채운다.** 리랭커는 매 요청마다 20건을 돌리므로 정확도가 올라도
응답이 3초가 되면 서비스로 못 쓴다. **정확도와 지연을 같이 봐야 판단이 된다.**

⚠️ **R-2는 정확도보다 지연 실측이 먼저다.** 로컬 GPU가 RTX 3050 6GB인데
568M 리랭커 × 512토큰 × 20쌍이면 **2초 안팎**으로 계산된다. 사실이면 정확도 비교를
하기 전에 구성부터 바꿔야 한다. 측정 환경(GPU·`max_length`·배치)을 비고에 반드시 적을 것 —
안 적으면 나중에 다른 환경의 숫자와 섞여서 못 쓰게 된다.

⚠️ 필터를 걸면 HNSW 후보가 조용히 반토막 난다(`hnsw.iterative_scan` 확인).
R-4의 결과가 이상하면 이걸 먼저 의심할 것.

## Phase 3 — 데이터 확장 A/B

지표 1로는 잴 수 없다 — 정답이 "특정 QA 행 1개"라서, 유용한 신규 청크가 1위로 올라와도
**오답으로 채점된다.** 확장 데이터의 효과는 **지표 2(LLM 채점)로만** 잴 수 있다.

| ID | 추가한 소스 | 건수 | 인덱스 비중 | 지표 2 | Δ | 판정 |
|---|---|---:|---:|---:|---:|---|
| D-0 | **기준선** (AI Hub QA만) | 21,606 | 100% | | — | — |
| D-1 | + AI Hub 원천 청크 | | | | | |
| D-2 | + 유튜브 (doc2query) | | | | | |
| D-3 | + 유튜브 (원문 청크 직접) | | | | | |

D-2 vs D-3이 [data-expansion.md](data-expansion.md)의 **전략 B vs C 비교**다.
같은 원본 데이터를 두 방식으로 넣어 비교하므로 변수가 통제된다.

**커버리지 공백 질의셋에서도 따로 잴 것.** 전체 평균은 그대로인데 사료·행동 질문만
좋아졌다면 그게 성공이다. 평균만 보면 그 개선이 안 보인다.

⚠️ **전처리를 청킹보다 먼저.** 각주번호·표 캡션·영어 문단을 안 지우고 자르면
훼손된 텍스트가 그대로 청크에 들어가고 문맥만 더 끊긴다.
**청킹은 길이 문제를 푸는 기법이지 품질 문제를 푸는 기법이 아니다.**

⚠️ **AI Hub QA에는 고정 길이/재귀 청킹을 적용하지 않는다.** 답변이 여러 질문에
통으로 답한 한 덩어리라 질문 조각과 1:1 대응이 안 된다. QA는 C-5(Parent-Child)
계열의 **의미 분해**만 해당하며, 그 실험은 위 R-6이다. C-1~C-4는 원천데이터와
확장 데이터(유튜브·블로그) 대상이다. 근거는
[dataset-analysis.md](dataset-analysis.md) "텍스트 길이" 절.

검색 상위 5건만 썼으면 4건을 놓쳤다는 뜻이고, 후보를 20건까지 넓히는 근거다.
점수 변별력도 검색 0.725~0.675(폭 0.05) vs 리랭커 0.872~0.456(폭 0.42).
