# Phase 1-b (R-2a) — 리랭커 `bge-reranker-v2-m3` (후보 20 → 5)

**측정일** 2026-08-18 · **판정과 해석은** [../../experiments.md](../../experiments.md) Phase 1 절

**변수 하나: 리랭커의 유무.** 임베딩·평가셋·후보 추출이 전부 B-0과 같고,
벡터 검색 상위 20건을 cross-encoder로 다시 정렬한 것만 다르다.

Phase 1의 첫 실험이자 **3종 병행의 첫 사용례**다. 같은 변경을 A·K·B에 각각 걸어
"이 기법이 진짜인가, 한 모델의 약점을 메운 것인가"를 갈랐다.

---

## 측정 조건

| 항목 | 값 |
|---|---|
| 리랭커 | `BAAI/bge-reranker-v2-m3` (568M) · fp16 · `max_length` 512 |
| 후보 | 벡터 검색 상위 **20건** → 리랭킹 |
| GPU | RTX 3050 6GB |
| 기준선 | **arm마다 자기 B-0** (A→E-7 · K→E-6 · B→E-2). 모델끼리 섞어 비교하지 않는다 |
| 지연 표본 | arm당 100건, **한 요청 = 질의 1건 × 후보 20쌍**(서비스 형태) |

⚠️ **지연 측정과 정확도 실행은 배치가 다르다.** 정확도는 16질의씩 몰아서 돌리는데
(2,399건을 11분에 끝내려고), 그 배치로 지연을 재면 **실제보다 좋아 보인다.**
표의 지연은 전부 한 질의씩 잰 값이다.

---

## 결과

| arm | 임베딩 | Hit@1 | Hit@5 | Hit@20 | MRR | ΔMRR (자기 B-0 대비) | 95% 구간 | 판정 |
|---|---|---:|---:|---:|---:|---:|---:|---|
| **R-2a-A** | arctic base | 0.394 | 0.594 | 0.693 | **0.487** | **+0.0238** | [+0.0115, +0.0358] | 우세 |
| **R-2a-K** | arctic-ko | 0.392 | 0.598 | 0.704 | **0.488** | **+0.0204** | [+0.0081, +0.0332] | 우세 |
| **R-2a-B** | bge-m3 | 0.387 | 0.585 | 0.664 | **0.478** | **+0.0834** | [+0.0708, +0.0961] | 우세 |

**세 arm 모두 올랐다 → 기법이 진짜다.** 한 모델에서만 올랐다면 그 모델의 약점을
메운 것일 뿐인데, 그건 전혀 다른 결론이고 단일 모델로는 구분되지 않는다.

### Hit@20이 B-0과 정확히 같은 것은 정상이다

리랭킹은 **후보 20건 안에서만** 순서를 바꾼다. 정답이 20위 안에 있느냐 없느냐는
구조상 바뀔 수 없다. 세 arm 모두 B-0과 소수점 셋째 자리까지 같다
(A 0.693 · K 0.704 · B 0.664) — **채점이 의도대로 돌았다는 확인**이기도 하다.

→ **리랭커의 상한은 벡터 검색의 Hit@20이다.** A는 0.693이 천장이고, 그걸 올리려면
R-3(하이브리드)·R-5(후보 50)처럼 **후보 자체를 넓히는** 실험이어야 한다.

### 지연 — 추정이 4배 비관적이었다

| arm | 검색 p50 | 리랭킹 p50 | **e2e p95** |
|---|---:|---:|---:|
| A | 0.24ms | 492ms | **573ms** |
| K | 0.23ms | 553ms | **621ms** |
| B | 0.23ms | 564ms | **626ms** |

로드맵은 "3050에서 20쌍 리랭킹이 2초 안팎"으로 계산했고 **Phase 1의 첫 벽**이 될 것으로
봤다. 실측은 **p95 573~626ms**다. 568M 모델을 그대로 두고 정확도 실험을 계속해도 된다.

⚠️ 이 값에 **LLM 생성이 빠져 있고** 검색은 로컬 numpy 브루트포스다.
Phase 2에서 pgvector와 생성이 붙으면 다시 재야 한다.

## ⚠️⚠️ 가장 중요한 결과 — 리랭커가 임베딩 모델 격차를 거의 흡수한다

3종 병행이 답하려던 **질문 ①**("모델 간 격차가 리랭커 뒤에도 남는가")이다.

| 비교 | ΔMRR | 95% 구간 | 판정 |
|---|---:|---:|---|
| **B-0**: A → bge-m3 | **−0.0683** | [−0.0801, −0.0562] | A 우세 |
| **R-2a**: A → bge-m3 | **−0.0087** | [−0.0164, −0.0007] | A 우세(경계) |
| B-0: A → K | +0.0048 | [−0.0023, +0.0116] | 차이 없음 |
| R-2a: A → K | +0.0014 | [−0.0032, +0.0062] | 차이 없음 |

**격차의 87%가 사라졌다.** Phase 0에서 "계열 교체가 유일한 실질 개선(+0.073)"이었는데,
리랭커를 붙이자 그 개선의 대부분이 무의미해졌다 — bge-m3도 리랭킹 뒤에는 0.478로
arctic(0.487)에 거의 붙는다. 통계적으로는 여전히 유의하지만(구간이 0을 아슬하게 제외)
**실무적으로 −0.009는 모델 선택의 근거가 되기 어렵다.**

→ **Phase 2의 우선순위가 바뀐다.** "어느 임베딩 모델을 적재할 것인가"에 쓸 시간을
줄이고, 리랭커를 전제로 한 구성(후보 수·리랭커 크기·지연)에 쓰는 게 맞다.

→ **질문 ②(A와 K의 동률)도 유지됐다.** 격차가 오히려 +0.0048 → +0.0014로 더 줄었다.
다국어인 A를 택하는 근거가 한 겹 더 단단해졌다 — Phase 3의 영어 문서 편입과 맞물린다.

## R-6(복합 질문)의 절반을 리랭커가 가져갔다

Phase 0의 발견은 "복합 질문 파생이 단일 주제 대비 9~13%p 낮고, **모델 교체로는
안 풀린다**"였다. 리랭커는 그 격차를 절반으로 줄인다.

| arm | B-0 격차 | **R-2a 격차** | 회복분 |
|---|---:|---:|---:|
| A | −12.6%p | **−6.9%p** | 5.7%p |
| K | −11.2%p | **−5.7%p** | 5.5%p |
| B | −9.6%p | **−5.9%p** | 3.7%p |

**세 모델 전부에서 절반씩 줄었다.** 복합 질문이 한 벡터에 여러 주제를 담아 검색이
흐려지더라도, 후보 20건 안에 정답이 들어와 있으면 cross-encoder는 질문과 문서를
같이 보기 때문에 골라낼 수 있다는 뜻이다.

→ **R-6(의미 분해)은 여전히 필요하지만 기대 효과를 낮춰 잡아야 한다.**
남은 −6%p가 R-6이 노릴 몫이고, 그중에서도 **정답이 top-20에 아예 못 들어온 경우**는
리랭커가 손댈 수 없어 R-6이나 R-3의 영역이다.

## 재현

```bash
backend/.venv/Scripts/python.exe scripts/1b_rerank.py \
  --emb-dir data/embeddings/snowflake_snowflake_arctic_embed_l_v2_0 \
  --emb-dir data/embeddings/dragonkue_snowflake_arctic_embed_l_v2_0_ko \
  --emb-dir data/embeddings/baai_bge_m3 \
  --arm-id embeddings/snowflake=R-2a-A --arm-id dragonkue=R-2a-K --arm-id baai=R-2a-B \
  --reranker BAAI/bge-reranker-v2-m3 --candidates 20 --max-length 512 \
  --baseline R-2a-A=phase0-embedding:E-7 \
  --baseline R-2a-K=phase0-embedding:E-6 \
  --baseline R-2a-B=phase0-embedding:E-2 \
  --phase 1 --exp-id phase1-r2a --measured-at 2026-08-18 \
  --title "R-2a — 리랭커 bge-reranker-v2-m3 (후보 20 → 5)" \
  --save docs/results/phase1-r2a
```

arm당 약 11분(2,399질의 × 후보 20). **arm이 끝날 때마다 `data/rerank_cache/`에
질의별 순위를 남기므로** 중간에 멈춰도 완주한 arm은 다시 돌지 않는다.
리랭커·`max_length`·후보 수·임베딩 경로가 하나라도 바뀌면 지문이 달라져 재계산한다.
캐시를 무시하려면 `--refresh`.

### 위 "모델 간 격차" 표는 `ranks.csv`에서 나온다

`metrics.json`의 `paired_tests`는 **자기 B-0 대비**만 담는다(그게 Phase 1의 기록 단위다).
arm끼리의 비교는 원자료에서 직접 계산한다:

```python
import pandas as pd, numpy as np
r2 = pd.read_csv("docs/results/phase1-r2a/ranks.csv")
d = 1 / r2["R-2a-B"] - 1 / r2["R-2a-A"]            # 질의별 역순위 차
rng = np.random.default_rng(42)
boot = [d.values[rng.integers(0, len(d), len(d))].mean() for _ in range(2000)]
print(d.mean(), np.percentile(boot, [2.5, 97.5]))
```
