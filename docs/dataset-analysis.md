대상: AI Hub `59.반려견 성장 및 질병 관련 말뭉치 데이터`
(zip 18개를 직접 파싱해 실측한 수치. 2026-08-12)

## 구성

성격이 전혀 다른 두 덩어리가 들어있다.

| | 라벨링데이터 (TL/VL) | 원천데이터 (TS/VS) |
|---|---|---|
| 건수 | **21,606건** | 239건 |
| 형태 | 보호자 질문 ↔ 전문가 답변 | 수의학 논문/교재 본문 |
| 평균 길이 | 질문 330자 / 답변 395자 | **16,275자** (최대 295,987자) |
| 용량 | 22.7MB | 2.4MB |
| 판정 | **RAG 지식베이스 본체** | **1차 스코프 제외** |

**JSON 파일 1개 = QA 1쌍**이다. 21,606은 zip 10개 안의 JSON 파일 총 개수.

## 1. 라벨링데이터 (질의응답) — 품질 양호

### 스키마

```json
{
  "meta": { "lifeCycle": "노령견", "department": "안과", "disease": "제3안검탈출증" },
  "qa": {
    "instruction": "너는 반려견 건강 상담을 잘하는 전문가야. 보호자의 질문에 정확히 답변해줘.",
    "input":  "진돗개의 수컷이 녹내장으로 의심됩니다. ... 안약으로만 치료가 가능한지 궁금합니다.",
    "output": "보호자께서 진단하신 내용에 따르면, 반사판으로 인해 나타나는 녹색빛은..."
  }
}
```

| 항목 | 결과 |

| 빈 input/output | **0건** |
| 질문 완전중복 | 2건 (고유 21,604) |

#### ⚠️ 2026-08-18 — "불일치 1건"의 정체는 공백이었다 (Phase 0-1에서 발견)

`department`가 `" 치과"`(앞에 공백)인 행이 1건 있다. 진료과를 잘못 적은 게 아니라
**문자열에 공백이 붙어 있는 것**이다. 그대로 두면:

- 진료과가 **6종으로 집계**된다 (`치과 878` + `치과 1`)
- Phase 1-d의 `WHERE department = '치과'` 필터가 이 행을 **에러 없이** 놓친다

→ `scripts/01_prepare_data.py`에서 모든 메타값을 `strip()` 한다.
수정 후 치과 879로 이 문서 수치와 일치한다.

**교훈:** "불일치 1건"처럼 건수만 적어두면 원인을 모른 채 넘어간다.
1건이라도 **무엇이 어떻게 다른지**를 봐야 처리 방법이 갈린다.

→ 전처리에 시간을 거의 안 써도 된다.
→ **Validation 2,400건을 평가셋으로 쓸 수 있을 만큼 분리가 깨끗하다.**

#### ⚠️ 2026-08-18 정정 — "청킹 불필요"는 틀린 판정이었다

이 자리에 원래 **"청킹 불필요. 임베딩 1건 = QA 1쌍으로 그냥 넣으면 된다"** 라고 적혀
있었다. **평균 330자만 보고 내린 판정이라 틀렸다.** 평균은 이 데이터의 문제를 못 잡는다.

**청킹이 푸는 문제는 두 개인데, 하나만 확인하고 판정했다.**

| 문제 | 확인 여부 | 실측 결과 |
|---|---|---|
| ① 모델 입력 길이 초과 → 잘림 | 확인함 | **문제 없음** (조건부) |
| ② 한 벡터에 여러 주제 → 검색 정밀도 하락 | **확인 안 함** | **문제 있음** |

**① 잘림 — 후보 모델에 한해 문제 없다.**

| 모델 상한 | input 초과 | input+output 초과 |
|---|---:|---:|
| 512 tok (구형 BERT 계열) | 1,883건 (**8.7%**) | 9,173건 (**42.5%**) |
| 8,192 tok (bge-m3 · KURE-v1 · gte 계열) | 0건 (0%) | 0건 (0%) |

후보 3종이 전부 8,192라 잘리지 않는다. 하지만 이건 **모델에 의존하는 판정**이지
데이터의 성질이 아니다. 512짜리 모델을 쓰면 질문의 8.7%가 잘리고,
질문+답변을 인덱싱하면(roadmap R-1 실험) **42.5%가 잘린다.**
→ 모델을 바꿀 때마다 다시 판단해야 한다.

**② 주제 혼합 — 여기가 진짜 문제다.**

질문 하나에 서로 다른 주제가 몇 개나 들어있는지 세어봤다
(`요?`/`까?`/`나요`/`ㄹ까요`/`는지요`/`습니까`/`궁금` 출현 횟수 기준).

| 질문 표현 수 | 건수 | 비율 |
|---|---:|---:|
| 1개 이하 | 14,013 | 64.9% |
| 2개 | 4,066 | 18.8% |
| 3개 | 1,757 | 8.1% |
| **4개 이상** | **1,770** | **8.2%** |

1,000자를 넘는 543건은 **평균 5.1개**의 질문 표현을 담고 있다 (전체 평균 1.5개).

실제 최장 질문(3,208자, 질문 표현 11개)을 열어보면:

```
"3개월 강아지 2차 접종 ... 증상 일지는 주간 단위로 확인해 주세요 ...
 핥음·긁음이 심하면 ... 환경 변화를 최소화해 주세요 ..."
```

접종 시기 · 증상 기록 · 피부 자극 · 환경 관리가 **한 건에 뒤섞여 있다.**
이걸 벡터 하나로 임베딩하면 그 벡터는 **어느 주제도 제대로 대표하지 못하고**,
결과적으로 "어떤 질문에든 어중간하게 걸리는" 행이 된다.

이건 [rag-design.md](rag-design.md)가 원천데이터를 비판할 때 쓴 논리
(**"긴 청크 편향 — 한 청크에 여러 주제가 섞이면 어떤 질문에든 어중간하게 걸린다"**)와
정확히 같은 것이다. **그 논리가 우리 QA 데이터 상위 8~16%에도 그대로 적용된다.**

⚠️ 판정을 보수적으로 읽을 것: 질문 표현 2개는 같은 주제를 두 번 물은 것일 수 있다
(`"~인지 궁금합니다. ~하면 될까요?"`). **명백한 복합 질문은 4개 이상인 8.2%**이고,
3개 이상까지 넓히면 16.3%다. 2개(18.8%)는 표본을 눈으로 봐야 판정된다.

**2026-08-18 보정 — 종결어미 세기로는 못 잡는다 (LLM 정답과 대조 실측).**

Phase 0-2에서 질문 표현이 2개뿐인데 이갈이(치과)와 은행잎 섭취(중독)가 섞인
580자 행이 나왔다. 그래서 길이 층화 표본 40건을 LLM에 "독립된 주제가 몇 개인가"로
물어 정답을 만들고, 규칙들과 대조했다.

**LLM 기준 실제 복합(주제 2개+) 비율은 68%다.** 우리 규칙은 전부 크게 과소 추정했다.

| 규칙 | 해당 건수 | 정밀도 | 재현율 | **F1** |
|---|---:|---:|---:|---:|
| 종결어미 3개+ (구버전) | 3,527 (16.3%) | 1.00 | 0.30 | 0.46 |
| 종결어미 3개+ 또는 (2개 & 500자+) | 4,197 (19.4%) | 1.00 | 0.37 | 0.54 |
| 전환 접속사 1개+ (`그리고`/`또한`/`추가로`…) | 8,074 (37.4%) | 0.88 | 0.52 | 0.65 |
| 의문표현 3개+ (의문사·`?` 포함) | 9,512 (44.0%) | 0.82 | 0.67 | **0.73** |
| 의문표현 5개+ | 6,259 (29.0%) | 0.94 | 0.59 | **0.73** |
| **길이 400자+ (그냥 길이)** | 5,845 (27.1%) | 1.00 | 0.59 | **0.74** |

**결론 셋:**

1. **종결어미만 세는 방식이 제일 나쁘다** (재현율 0.30). `"~문의드립니다"`로 끝나는
   문어체 질문은 종결어미가 **0개**인데 주제는 3~4개인 경우가 흔하다. 원리적으로 못 잡는다.
2. **정규식을 정교하게 다듬어도 단순 길이를 못 이긴다.** 의문표현·전환 접속사를
   추가해도 F1 0.73인데 `길이 400자+` 하나가 0.74다. 주제 수와 종결어미 수는 애초에
   다른 것이라서 그렇다 — 한 주제를 다섯 번 물을 수도, 다섯 주제를 서술문으로 쓸 수도 있다.
3. **그러므로 규칙은 판정이 아니라 선별(screening)이다.** 최종 판정은 Phase 1-f에서
   실제로 분해해보고 내린다. 분해 결과가 1개면 원본을 그대로 둔다 — **자기 검증 구조**라
   선별 규칙이 다소 헐거워도 안전하다.

→ **R-6 선별 기준: `길이 400자+ 또는 의문표현 3개+`** (11,368건, 52.6%).
재현율을 우선한다. 오탐은 분해 단계에서 걸러지지만 미탐은 영영 못 잡기 때문이다.

⚠️ LLM 정답 자체도 절대값으로 믿을 것은 아니다. "주제 2개"의 경계가 느슨해
68%가 과대일 수 있다. **규칙 간 상대 비교**에만 쓴다.

#### 그래서 무엇을 하는가 — 고정 길이 청킹은 답이 아니다

**"청킹이 필요하다"는 맞지만, `RecursiveCharacterTextSplitter`로 400자씩 자르는 것은
이 데이터에 틀린 처방이다.** 잘린 조각이 이렇게 나온다:

```
"...주 1회 경과를 보며 강도나 빈도를 조정해 주세요, 환경 변화를 최소화해 주세요."
```

검색 대상으로 아무 쓸모가 없다. 게다가 답변(`output`)은 11개 질문에 **통으로** 답한
한 덩어리라 질문 조각과 1:1로 대응시킬 수도 없다.

→ **의미 단위 분해 후 payload 공유**가 맞다. [data-expansion.md](data-expansion.md)의
doc2query와 구조가 동일하다.

```
원본 1행 (3,208자, 주제 11개)
   ↓ LLM으로 독립 질문 분해
content="3개월 강아지 2차 접종은 언제 하나요"   payload=원본 답변 전체
content="강아지가 자꾸 핥고 긁는데 어떡하죠"     payload=원본 답변 전체   ← 같은 payload
content="증상 일지는 어떻게 기록하나요"          payload=원본 답변 전체
```

- 검색은 또렷한 단일 주제로, 답변은 원문 그대로 → **Parent-Child 구조 그 자체**
- `content`/`payload` 분리가 이미 있으므로 **스키마 변경 불필요**
- ⚠️ 같은 payload가 top-5를 독식하므로 **검색 후 payload 기준 중복 제거 필수**

**전량이 아니라 긴 것만 한다.** 64.9%는 이미 단일 주제라 건드리면 손해다.
길이·질문표현 수로 대상을 골라 **상위 8~16%에만** 적용하고, 효과는 지표 1로 잰다
([experiments.md](experiments.md) R-6).

### `instruction` 필드는 버려도 된다

40종 변형이 있지만 전부 같은 말이다.

```
"너는 반려견의 건강과 치료에 대한 풍부한 경험을 가진 수의사야. 보호자가 궁금한 점을 물어보면 알려줘."  607건
"너는 반려견의 건강 문제를 조기에 발견할 수 있는 전문가야. 보호자의 질문에 대해 답해줘."              578건
...
```

검색에 노이즈만 된다. 시스템 프롬프트는 새로 작성하는 게 맞다.

### output 특성 (안전장치 관련)

| 항목 | 비율 |
|---|---|
| '동물병원' 권유 포함 | 5,822 / 21,606 (27%) |
| '수의사' 언급 | 5,222 / 21,606 (24%) |
| **가격/비용 언급** | **648 / 21,606 (3%)** |

→ 답변의 27%만 병원 방문을 권유하고, 3%는 **구체적 비용을 언급**한다.
→ 의료 도메인이므로 면책·병원권유 문구를 **시스템 프롬프트에서 강제**해야 한다.
   원본을 그대로 노출하면 특정 치료비를 단정적으로 안내하는 꼴이 된다.

## 2. 원천데이터 (말뭉치) — ⚠️ 1차 제외 권장

239건. 논문 PDF를 기계번역 + 텍스트추출한 것이라 훼손이 심하다.

| 문제 | 비율 |
|---|---|
| 영어 원문 잔존 | **209/239 (87%)** |
| `~하였다` 오역 (문장 접합 실패) | 125/239 (52%) |
| 표/그림 캡션 본문 혼입 | 123/239 (51%) |

실제 예시:
```
"...위협 반응, 눈부심 반사, 직접 동공 빛 반사가 없었하였다."
"...t1/2가 짧아지고 청소율이 증가하였다.24 이러한 연구..."     ← 각주번호 24가 문장에 붙음
```

### 그 외 문제

- **평균 16,275자, 최대 295,987자** — 청킹 없이는 임베딩 자체가 불가능
- 분포 편향: 내과 167건 vs 치과 2건
- **Validation 원천데이터에는 안과·치과 zip이 아예 없다** (내과/외과/피부과만)

| split | 진료과 | 건수 |
|---|---|---:|
| Training | 내과 | 153 |
| Training | 외과 | 30 |
| Training | 피부과 | 24 |
| Training | 안과 | 3 |
| Training | 치과 | 2 |
| Validation | 내과 | 14 |
| Validation | 외과 | 7 |
| Validation | 피부과 | 6 |

### 판정

**"영영 버려라"가 아니라 "1차에는 넣지 마라".**
QA 21,606건만으로 5개 진료과가 이미 커버된다. 원천데이터가 채우는 빈틈이
뚜렷하지 않은데 리스크(검색 오염)는 확실하다.

나중에 쓴다면:
- QA가 답 못 하는 희귀 질환의 백업 지식원
- "출처: 한국수의과학회 논문" 형태의 근거 제시용

그때는 **별도 컬렉션으로 분리**하고 A/B로 효과를 확인한 뒤 결정.
