# 데이터셋 분석

대상: AI Hub `59.반려견 성장 및 질병 관련 말뭉치 데이터`
(zip 18개를 직접 파싱해 실측한 수치. 2026-08-12)

## 구성

성격이 전혀 다른 두 덩어리가 들어있다.

| | 라벨링데이터 (TL/VL) | 원천데이터 (TS/VS) |
|---|---|---|
| 건수 | **21,606건** | 239건 |
| 형태 | 보호자 질문 ↔ 전문가 답변 | 수의학 논문/교재 본문 |
| 평균 길이 | 질문 330자 / 답변 395자 | **16,275자** (최대 295,987자) |
| 용량 | 22.7MB | 2.4MB |
| 판정 | **RAG 지식베이스 본체** | **1차 스코프 제외** |

**JSON 파일 1개 = QA 1쌍**이다. 21,606은 zip 10개 안의 JSON 파일 총 개수.

## 1. 라벨링데이터 (질의응답) — 품질 양호

### 스키마

```json
{
  "meta": { "lifeCycle": "노령견", "department": "안과", "disease": "제3안검탈출증" },
  "qa": {
    "instruction": "너는 반려견 건강 상담을 잘하는 전문가야. 보호자의 질문에 정확히 답변해줘.",
    "input":  "진돗개의 수컷이 녹내장으로 의심됩니다. ... 안약으로만 치료가 가능한지 궁금합니다.",
    "output": "보호자께서 진단하신 내용에 따르면, 반사판으로 인해 나타나는 녹색빛은..."
  }
}
```

### 건수 분포

| 진료과 | Training | Validation | 합계 |
|---|---:|---:|---:|
| 내과 | 9,846 | 1,203 | **11,049 (51%)** |
| 외과 | 5,107 | 651 | 5,758 (27%) |
| 피부과 | 2,533 | 302 | 2,835 (13%) |
| 안과 | 970 | 115 | 1,085 (5%) |
| 치과 | 750 | 129 | **879 (4%)** |
| **합계** | **19,206** | **2,400** | **21,606** |

→ 치과·안과는 검색 후보 자체가 적어 답변 품질이 떨어질 수 있다.
   데모 시연 질문을 고를 때 감안할 것.

### 무결성 (이례적으로 깨끗함)

| 항목 | 결과 |
|---|---|
| 빈 input/output | **0건** |
| 질문 완전중복 | 2건 (고유 21,604) |
| 답변 완전중복 | 6건 (고유 21,600) |
| Training↔Validation 질문 누수 | **1건** |
| `department` 필드 vs 파일명 불일치 | 1건 |

→ 전처리에 시간을 거의 안 써도 된다.
→ **Validation 2,400건을 평가셋으로 쓸 수 있을 만큼 분리가 깨끗하다.**

### 메타데이터

**`lifeCycle`** — 의도적으로 균형을 맞춘 데이터. 필터로 쓰기 좋다.

| 값 | 건수 | 비율 |
|---|---:|---:|
| 성견 | 7,276 | 33.7% |
| 노령견 | 7,169 | 33.2% |
| 자견 | 7,161 | 33.1% |

**`disease`** — 45종이지만 **"기타"가 16,613건으로 77%**.
나머지 44종이 5,000건을 나눠 갖는다. 1건짜리 희귀 질병이 6개.

상위: 중성화수술 642, 무릎뼈 탈구 593, 중독 473, 골절 408, 심장사상충 396,
자궁축농증 367, 외이염 326, 위장관폐색 256, 아토피성 피부염 248, 방광염 228

→ **필터로 쓰기 어렵다.** 출처 표기용 보조로만.
→ 필터링은 `lifeCycle`(균등)과 `department`(5종) 위주로 설계.

### 텍스트 길이 (문자)

| | 평균 | 중앙 | p90 | 최대 |
|---|---:|---:|---:|---:|
| input | 330 | 258 | 629 | 3,208 |
| output | 395 | 317 | 719 | 3,707 |

→ **청킹 불필요.** 임베딩 1건 = QA 1쌍으로 그냥 넣으면 된다.

### `instruction` 필드는 버려도 된다

40종 변형이 있지만 전부 같은 말이다.

```
"너는 반려견의 건강과 치료에 대한 풍부한 경험을 가진 수의사야. 보호자가 궁금한 점을 물어보면 알려줘."  607건
"너는 반려견의 건강 문제를 조기에 발견할 수 있는 전문가야. 보호자의 질문에 대해 답해줘."              578건
...
```

검색에 노이즈만 된다. 시스템 프롬프트는 새로 작성하는 게 맞다.

### output 특성 (안전장치 관련)

| 항목 | 비율 |
|---|---|
| '동물병원' 권유 포함 | 5,822 / 21,606 (27%) |
| '수의사' 언급 | 5,222 / 21,606 (24%) |
| **가격/비용 언급** | **648 / 21,606 (3%)** |
| input이 질문 형태 | 17,646 / 21,606 (82%) |

→ 답변의 27%만 병원 방문을 권유하고, 3%는 **구체적 비용을 언급**한다.
→ 의료 도메인이므로 면책·병원권유 문구를 **시스템 프롬프트에서 강제**해야 한다.
   원본을 그대로 노출하면 특정 치료비를 단정적으로 안내하는 꼴이 된다.

## 2. 원천데이터 (말뭉치) — ⚠️ 1차 제외 권장

239건. 논문 PDF를 기계번역 + 텍스트추출한 것이라 훼손이 심하다.

| 문제 | 비율 |
|---|---|
| 영어 원문 잔존 | **209/239 (87%)** |
| `~하였다` 오역 (문장 접합 실패) | 125/239 (52%) |
| 표/그림 캡션 본문 혼입 | 123/239 (51%) |

실제 예시:
```
"...위협 반응, 눈부심 반사, 직접 동공 빛 반사가 없었하였다."
"...t1/2가 짧아지고 청소율이 증가하였다.24 이러한 연구..."     ← 각주번호 24가 문장에 붙음
```

### 그 외 문제

- **평균 16,275자, 최대 295,987자** — 청킹 없이는 임베딩 자체가 불가능
- 분포 편향: 내과 167건 vs 치과 2건
- **Validation 원천데이터에는 안과·치과 zip이 아예 없다** (내과/외과/피부과만)

| split | 진료과 | 건수 |
|---|---|---:|
| Training | 내과 | 153 |
| Training | 외과 | 30 |
| Training | 피부과 | 24 |
| Training | 안과 | 3 |
| Training | 치과 | 2 |
| Validation | 내과 | 14 |
| Validation | 외과 | 7 |
| Validation | 피부과 | 6 |

출처: (주)범문에듀케이션 182, 한국수의과학회 37, Wiley 9, 기타

### 판정

**"영영 버려라"가 아니라 "1차에는 넣지 마라".**
QA 21,606건만으로 5개 진료과가 이미 커버된다. 원천데이터가 채우는 빈틈이
뚜렷하지 않은데 리스크(검색 오염)는 확실하다.

나중에 쓴다면:
- QA가 답 못 하는 희귀 질환의 백업 지식원
- "출처: 한국수의과학회 논문" 형태의 근거 제시용

그때는 **별도 컬렉션으로 분리**하고 A/B로 효과를 확인한 뒤 결정.

**지식베이스 투입 불가 판정:**

1. **답변이 사람이 쓴 게 아니다** — Claude 기반 RAG가 생성한 출력.
   넣으면 "AI 답변을 근거로 AI가 답변"하는 2차 생성 구조가 되고 오류가 전파된다.
   (AI Hub QA는 실제 수의사 상담 기록 — 급이 다르다)
2. **답변 길이가 4배** (1,596자 vs 395자) — 긴 청크가 검색 상위를 독식하는 편향
3. **임베딩 모델 교체 필요** — cross-lingual 모델로 바꾸면 기존 21,606건 전부 재임베딩
4. **도메인 불일치** — 고양이·기타 동물 포함, 미국 기준 약품명/응급체계/비용
5. `[REDACTED]`가 문장 중간에 구멍으로 남음

**대신 이렇게 쓴다:** 실사용 질문의 **문체 참고 자료**.
